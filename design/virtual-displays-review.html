Design review 03 · 5 October 2026 · for Candela 1.3

Virtual displays

Add a display that exists only in Hyprland. You can use it as an extra screen on a tablet, a fixed-size stage to share or record, or a test bench at a resolution you don't own. Candela arranges it like any other display and recreates it at login. You see it through wayvnc, either in a window on your desk or from another device.

Target Omarchy 4.0.4 · Hyprland 0.56.2 · wayvnc 0.10.2 (Arch extra, not installed here) Ships in 1.3, after 1.2 Behaviour read in the Hyprland, wayvnc, neatvnc and portal sources; nothing tried on this desk yet Status awaiting your decisions
Scope

What it does

It creates, sizes, places and removes virtual displays, and recreates them at login. It shows a virtual display in a window on this desk, or offers it to another device over VNC behind a password. A virtual display is a full part of the arrangement: it appears on the canvas, takes the workspace plan, uses the safe apply and appears in doctor.

What it leaves alone

It never installs packages: when wayvnc or a viewer is missing, Candela says what to install. There's no RDP, Sunshine or web viewer, and no "switch all screens together" desktops, which existing plugins already cover. It doesn't take over your own ~/.config/wayvnc/config. A virtual display has no EDID, so it is SDR only.

Why Candela, given that a virtual-display plugin exists

The existing one bolts a screen to one side. Candela can make the virtual display a real member of the layout: snapped and placed like any display, homes in the workspace plan, never the place where another display's workspaces are parked, and stopped safely before it is removed. The last point matters: wayvnc would otherwise go on serving a real display (see below).

The parking guard
How it works

Outputs Candela owns, and wayvnc processes it supervises

Intent and lifecycle

intent.virtual lists each virtual display with its use, placement and how it is viewed. Its size, scale and position live with the other displays' fields. The service recreates any that are missing when the shell starts. Then the usual layout file gives each one its rule, and a hl.workspace_rule gives it its own named workspace as its default.

Viewing

Each virtual display gets up to two wayvnc processes, run as user units like the revert timer. Local serves a Unix socket in $XDG_RUNTIME_DIR (mode 0700) with authentication off, and Candela opens it in the first viewer it finds: wlvncc, gvncviewer, Remmina or TigerVNC. Network listens on one LAN address you pick, with RSA-AES, a generated password and a key file kept 0600 in Candela's state directory. Both run without --gpu, at 30 fps.

Removal and the guard

Removing a virtual display stops its viewers (wayvnc-exit), and only then calls hyprctl output remove. When a real display goes, the service moves any workspace Hyprland parked on a virtual display, and that doesn't live there, to the first real display. doctor lists virtual displays, their viewers and what listens on the network.

# CLI, everything the studio does
omarchy-candela virtual add stage [--size 1920x1080] [--scale 1] [--apart|--beside DP-2]
omarchy-candela virtual remove VIRTUAL-1
omarchy-candela virtual view VIRTUAL-1 window|network|off
omarchy-candela virtual restore           # what the service runs at start
Security

Nothing on the network by default

The local viewer uses a socket only your user can open. Network sharing is off until you turn it on, and is not restored at login unless you ask (decision 7).

Never without a password

Candela refuses to listen beyond this machine with authentication off. It never enables relax_encryption (unencrypted Apple and DES login, which also aborts on Arch's neatvnc) or WebSocket (which crashes it before login).

What a viewer can do

It shares your keyboard focus, so Super shortcuts from a tablet act on the whole desktop. Locking the session shows the lock screen on the virtual display too. The client list and Disconnect are in the inspector.

Test plan

Suite

The test compositor gains output create and remove, and stub wayvnc and wayvncctl. Tests cover: recreate at start, the named workspace, the order of removal (viewers before output), the parking guard, never listening beyond localhost without authentication, and the key file kept between restarts.

On this desk, warned, step by step

Create VIRTUAL-1 apart at 1920×1080; check the bar, the wallpaper and its named workspace with grim -o VIRTUAL-1 (grim can capture it); check that your workspaces 1–0 didn't move; remove it. Then, once you have installed wayvnc: the window viewer, the call picker (your hands), and a tablet over the LAN (your hands).

Unknown until tried

RealVNC on iPad and Android with RSA-AES. Whether a viewer window can stand in for a stage you watch while sharing. CPU cost: Hyprland reports full-frame damage, so neatvnc diffs every frame.

Decisions needed

Ten calls before code

  1. Names. VIRTUAL-1, VIRTUAL-2… in the canvas, the call picker and the rules, with your label ("Stage") beside it. The alternative is names you type. Recommend: VIRTUAL-n plus a label. Rules and pickers need a stable, plain name.
  2. Recreated at login. The service recreates kept virtual displays when the shell starts. Recommend: yes.
  3. Placement per display, Beside or Apart, with the use choosing the default: Extra screen beside, Stage and Test bench apart. Recommend: yes.
  4. No countdown for changes that only touch virtual displays. Revert undoes the last one. Recommend: yes. They can't blank a real screen.
  5. Its own named workspace, so a virtual display never takes 1–0, and so SUPER+number never jumps to a screen you may not be looking at. It can still be a home in the plan. Recommend: yes.
  6. The parking guard: a workspace Hyprland parks on a virtual display, which doesn't live there, is moved to a real display at once. Recommend: yes.
  7. Network sharing: Candela runs its own wayvnc with RSA-AES, a generated password and a kept key, on one LAN address you pick, off at each login unless you choose otherwise. Alternatives: use your own wayvnc config, or no network sharing in Candela at all. Recommend: Candela's own, off at login. Your use 1 needs it, and a safe default is the point.
  8. macOS Screen Sharing is refused, with the reason shown, because it can only connect unencrypted. Recommend: yes. TigerVNC on the Mac works.
  9. The local viewer: the first one found among wlvncc, gvncviewer (installed here), Remmina and TigerVNC, over a private socket. Recommend: yes.
  10. Release: 1.3, after 1.2 is out, with the desk probe as the first step. Recommend: yes.

Once these are decided, the approved version goes into DESIGN.md as §12.
