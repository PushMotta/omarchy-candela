Design review 01 · 3 September 2026 · Omarchy shell plugin

Displays for Omarchy

A displays product for a keyboard-driven desktop: arrange displays, drive them at their real capabilities, and put them into the right colour mode with the compositor telling the truth in physical units. Two surfaces, one backend, zero programmer's art.

Target Omarchy 4.0.2 · Hyprland 0.56.2 (Lua) Form user plugin at first-party quality Mockup tokens real colors.toml and shell.toml values Status awaiting review before QML
Thesis

What exists

Omarchy has a brightness popup with scale presets and an enable list. Everything else is "open monitors.lua in an editor". Nothing knows what the panel can do, and nothing says what the compositor is actually sending.

What we build

A popup for the daily controls and a studio overlay for arrangement, signal, geometry and colour. One control, SDR · Wide · HDR, maps to the five Hyprland fields that matter. Every risky change previews live and reverts itself unless kept.

The bar to clear

Not "has the knobs". A colour professional sees the panel described in cd/m² and chromaticities, flips to HDR once, and never opens a config file. A laptop user sees brightness, scale, rotation, and nothing in the way.

Callouts

  1. 1

    Hero names the display, not the panel. Title is connector plus model; the meta line is the live state Hyprland reports: mode, refresh, scale and output format. Chips switch which display the popup drives; the focused one is preselected.

  2. 2

    SDR white in cd/m², only in HDR. Replaces the meaningless "brightness of SDR" multiplier. Range is 80 to the panel's declared max-average luminance, with 203 marked in the accent colour. Drives sdr_max_luminance. Hyprland's default is 80, which is why HDR desktops look washed out.

  3. 3

    One colour control, three honest states. Options appear only when the EDID supports them. The caption states the resulting output so the user never has to infer what "HDR" did.

  4. 4

    Display list carries state tags. Focused, HDR, mirror. Enter toggles enable; the last enabled display refuses to be disabled.

  5. 5

    Two actions, no settings sprawl. Identify flashes each connector on its own screen. Arrange opens the studio. Everything else lives there.

  1. 1

    Canvas in logical pixels, because that is what Hyprland positions in. Edges snap, the guide shows the snap, overlap turns the block urgent and disables Apply. Mirrors stack with a badge. The caption prints the numbers.

  2. 2

    Panel section states EDID truth, including the blank-serial caveat this desk has. The gamut plot draws the panel's own primaries over sRGB, P3 and BT.2020 outlines. Capability line is what gates the colour options.

  3. 3

    Colour section is the whole HDR story in four rows: mode, SDR white, SDR transfer, ICC. Saturation and everything with a physical footgun sits behind Advanced with a caption explaining it.

  4. 4

    Advanced is a row, not a tab. Preset override (auto…hdredid), min / max / average luminance with EDID values as placeholders, supports_hdr and supports_wide_color overrides, and the global auto-HDR switch.

  5. 5

    Actions with the keys printed. Apply previews live and starts the countdown below. Revert returns to the persisted layout. The hint line is caption size and reads left to right in the order you use it.

SDR white

203 cd/m² by default, clamped to the panel's max-average luminance. Ceiling is sustained full-field, not peak: mapping SDR white to peak makes a white window dim under the panel's brightness limiter.

Transfer

Hyprland defaults SDR to gamma 2.2 since 0.55. Exposed as Default · 2.2 · sRGB with the caption "choose sRGB if terminals look lighter than before 0.53".

Auto HDR

render:cm_auto_hdr is on by default and has two open bugs when cm ≠ srgb. It is shown in Advanced and never changed silently.

Architecture

Bash backend, QML front, generated Lua

Backend

One command, omarchy-displays, with subcommands: state, apply, keep, revert, persist, identify, hdr, edid, icc. Bash 5 and jq in the house style; reads hyprctl -j, edid-decode and DRM sysfs. JSON in, JSON out, so every UI action is also a keybinding.

Persistence

A generated file at ~/.local/state/omarchy/toggles/hypr/displays-layout.lua, which Omarchy already loads after the user's monitors.lua on every reload. One hl.monitor per managed display with every managed field explicit. The user's own file is never parsed or edited.

Safety

Apply saves the previous live state, applies through hyprctl eval for every display in one chunk, and spawns a detached 15 s revert timer. The shell shows the countdown but does not own it, so the revert fires even if the shell dies at 10-bit on a Mesa-rendered laptop.

Decisions needed

Six calls before QML

  1. Two surfaces, this section order. Approve, or move things between popup and studio.
  2. SDR white default at 203 cd/m², clamped to max-average. Agree, or anchor differently for your panels.
  3. Wide as a first-class third state, or folded under Advanced.
  4. Plugin id and name. pmotta.displays and "Displays" are placeholders.
  5. Generated state file (recommended) versus a managed block inside monitors.lua.
  6. Probe availability for validating the SDR-white anchor and EDID luminances on the MateViews.
Findings from today's live tests

10-bit did not crash this shell

DP-2 ran XBGR2101010 for 12 s with the shell's PID unchanged and no coredump. The trace in issue #9804 runs through Mesa's EGL, so that shell rendered on an integrated GPU. Hybrid laptops stay at risk; the detached revert timer covers them.

HDR entry works

bitdepth = 10, cm = "hdr" gave colorManagementPreset: hdr within a second. sdrMaxLuminance stayed at Hyprland's default of 80, which is the washed-out desktop in one number. The tool writes SDR white on every HDR entry.

Never mix explicit and auto positions

Declaring DP-2 alone at 2400x0 moved DP-1 to 4800x0. Declaring both in one chunk held. Every apply declares every display, and hyprctl reload is the revert primitive.
